# 個人開発向け構成の選び方

## 1. Cloudflare Workers + D1

最も低い初期コストを優先し、SQL が単純で API が軽い場合に選びます。静的配信、API、DB を Cloudflare に集約でき、運用対象が少なくなります。

ただし、複雑な結合や集計を DB へ任せたい場合、または認証・権限モデルが重くなった場合は、D1 だけで粘らず Firebase または PostgreSQL を持つ構成へ移ります。

## 2. Firebase Hosting + Authentication + Firestore

リアルタイム更新やログインを早く実装したい場合に選びます。認証とクライアント SDK が揃うため、Web とモバイルを並行して作るプロトタイプに向いています。

Firestore はドキュメント指向です。複数テーブルの結合や任意の集計を中心に考えるアプリでは、データモデルを先に試作してから採用します。セキュリティルールは API の代わりにデータアクセスを守るため、アプリコードと同じ Pull Request でレビューします。

## 3. AWS Serverless

他の AWS サービス、細かな IAM 分離、イベント駆動処理が必要になった段階で選びます。柔軟性は高い一方で、アカウント設定、リージョン、複数サービスの権限を管理する負担があります。

個人開発の最初から選ぶ理由は「AWS を使いたい」ではなく、Cloudflare や Firebase では満たせない要件があることです。

## 選択の順序

1. データアクセスが単純で、低コストを最優先するなら Cloudflare を選びます。
2. 認証とリアルタイム更新が製品価値の中心なら Firebase を選びます。
3. AWS 固有サービスや厳密なクラウド権限設計が必要なら AWS Serverless を選びます。

同じ機能を複数のクラウドへ二重実装しません。最初に一つを選び、計測・障害・開発速度を根拠に移行を判断します。
